# Remediation Log — Meridian App Sec Hardening

Before/after comparison: [`vulnerable-baseline` → `main`](../../compare/vulnerable-baseline...main)

| # | Finding | Risk | Fix | Commit |
|---|---|---|---|---|
| 1 | Hardcoded admin token in `legacy_admin_check`, using `assert` for an auth check | A hardcoded secret in source code is visible to anyone with repo access — the exact failure pattern that caused Meridian's real breach. `assert` statements are stripped when Python runs with `-O`, silently disabling the check entirely. | Removed the dead function and its hardcoded token. | [`5e6d26a`](../../commit/5e6d26a) |
| 2 | Hardcoded fallback API keys in `get_api_key` | If `VALID_API_KEYS` was ever unset (misconfigured deploy, dropped env var), the app fell back to known dev keys — silently granting access with a publicly-guessable credential instead of failing safely. | App now fails closed: startup errors out if `VALID_API_KEYS` is unset, rather than falling back to a default. | [`110d56b`](../../commit/110d56b) |
| 3 | CORS wildcard (`allow_origins=["*"]`, all methods, all headers) | Wildcard CORS lets any website make authenticated requests to the API from a victim's browser — a direct path to cross-site data theft on a system holding patient records. | Restricted to an explicit `ALLOWED_ORIGINS` env var; narrowed allowed methods and headers to what the API actually uses. | [`58d7493`](../../commit/58d7493) |
| 4 | Audit log stored in memory only | An in-memory list vanishes on every restart/redeploy — destroying the audit trail regulators require under UK GDPR / NHS DSPT at the exact moment it's needed most. | Audit log now persists to SQLite (`data/audit_log.db`), gitignored. | [`c3f9c3b`](../../commit/c3f9c3b) |
| 5 | Patient and appointment data stored in memory only | Same failure as #4, applied to the actual patient records the app exists to protect — a restart silently wipes registered patients and appointments with no recovery path. | Patient and appointment data now persist to SQLite alongside the audit log. | [`f769121`](../../commit/f769121) |
| 6 | Bandit CI step blocked on any finding, any severity/confidence | A single LOW-severity, LOW-confidence hit (often a false positive) failed the whole pipeline — teaching developers to ignore or bypass the security gate rather than trust it. | Split into a blocking HIGH-severity step and a non-blocking MEDIUM-severity informational step, matching the project's "block on HIGH, warn on MEDIUM" spec. | [`a9b0d6e`](../../commit/a9b0d6e) |
| 7 | TruffleHog scan used `github.event.before`, which is all-zeros on a repo's first push | TruffleHog can't diff against a commit that doesn't exist — the scan errors out or silently skips exactly the commit range containing the original, unremediated codebase. | Added a check for the all-zero SHA; falls back to a full-repository scan instead of a diff when there's no valid "before" commit. | [`29ecdf4`](../../commit/29ecdf4) |
| 8 | `requirements.txt` used unpinned `>=` floors | Same input, different day, different installed packages — breaks reproducibility of pip-audit results and lets a compromised or buggy upstream release enter the build with no review step. | Pinned all eight dependencies to exact, pip-audit-verified clean versions. | [`17839c1`](../../commit/17839c1) |
| 9 | Workflow file at `workflows/` instead of `.github/workflows/` | GitHub Actions only auto-discovers workflows under `.github/workflows/` — every fix above was committed to a pipeline definition that had never actually run. | Moved the file with `git mv` to preserve history; pipeline is now discoverable by GitHub Actions. | [`b5059f0`](../../commit/b5059f0) |
